## 1. The contract as it exists

**Measurement ID:** `G-94L9B8WZ12`, one id, no drift. Loaded from
`googletagmanager.com/gtag/js` by `analytics.js`, and only after a stored consent choice of
`accept`.

There are **two** senders, and both are part of the contract:

| sender | events | parameter control |
|---|---|---|
| `analytics.js` | `page_view`, `lead_form_start`, `contact_click`, `resource_download`, `generate_lead`, `ga4_debug_ping` | closed 8-key allow-list, e-mail/phone redaction, 100-char cap |
| `main.js` `initGA` | `bot_click`, `click_email` and the CTA family | its own closed 15-key allow-list, same redaction, 120-char cap |

`main.js` was not in the original brief and is worth naming plainly: it is a second delegated GA4
sender that calls `gtag` directly. It is disciplined — hrefs are reduced to a scheme token or a
hostname, never a full URL, and its CTA parameters come from author-set `data-*` attributes, never
from a form field — but it exists, and this gate holds it to the same rules.

GA4's own enhanced measurement also emits `scroll`. That is Google's built-in, not ours.

### Inventory

| event | trigger | RU | RO | parameters | PII risk | live verified | required for v1 |
|---|---|---|---|---|---|---|---|
| `page_view` | one explicit send per page (`send_page_view: false`) | yes | yes | scrubbed location, path, title, language | none | **yes** | yes — entry |
| `lead_form_start` | first `focusin` inside `#consultForm` / `#qFormV86` / `#qForm`, deduped per form+path | yes | yes | source, page_slug, site_language, form_name | none | **yes** | yes — start |
| `contact_click` | click on a `mailto:` / `tel:` / `t.me` / `wa.me` anchor | yes | yes | + contact_method (categorical) | none | **yes** | yes — intent |
| `generate_lead` | `thank-you.html?tool=…` with a same-origin referrer, deduped by `sid` in sessionStorage | yes | yes | + form_name, lead_type | none | **yes** | yes — conversion |
| `resource_download` | click on a download anchor or known extension | yes | yes | + file_extension, file_name | none | not exercised | no |
| `bot_click`, `click_email`, CTA family (`main.js`) | delegated anchor clicks with `data-cta-*` | yes | yes | 15-key allow-list, author-set attributes | none | **yes** (observed) | no |
| `ga4_debug_ping` | `?debug_ga4=1` only | n/a | n/a | debug only | none | n/a | no |

The **v1 journey is covered by the existing events**: entry (`page_view`), start
(`lead_form_start`), intent (`contact_click`), conversion (`generate_lead`). No event was invented
to make the funnel prettier, and none was needed.

`data-event` and `data-ga` attributes in the HTML are **not** read by `analytics.js`; they are
consumed only by `main.js`. Nothing else reads them.

## 2. The P1, found live

Event parameters were always filtered, and the URL allow-list already rejected identifiers. But
`gtag` attaches `page_location` to **every** event from `document.location`, and only the explicit
`page_view` overrode it. On the conversion page the beacons were:

    en = page_view
      dl = https://www.finmentor.md/thank-you.html?tool=xray_extended          ← scrubbed
    en = generate_lead
      dl = https://www.finmentor.md/thank-you.html?tool=xray_extended&sid=SYNTHETIC-UAT-0001

The submission id reached GA4 in the page address of the conversion beacon. Its event parameters
were clean; the leak was the address. Reading the code would not have shown this — the parameter
filter looks airtight, and it is. Only the network told the truth.

**The fix** sets the scrubbed location on the **config**, which makes the URL allow-list
authoritative for every event from every sender — including `main.js`, which would otherwise have
kept sending the raw address. `trackBusiness` also passes it explicitly, applied *after* the caller
parameters so it cannot be overridden and does not depend on config ordering.

No new event, no new parameter, no new architecture. Shipped as PR **#23**, merged `b57ac25`.

## 3. Live UAT results

`qa/ga4-live-uat.mjs` — headless Chrome, real network beacons, **18 checks, 0 failures**, run
against `https://www.finmentor.md` after the fix was published.

| proof | result |
|---|---|
| no Google tag and no beacon before consent is granted | **PASS** |
| RU landing: tag loads exactly once, exactly one `page_view` | **PASS** |
| RO landing: tag loads exactly once, exactly one `page_view` | **PASS** |
| every beacon carries `G-94L9B8WZ12` and no other id | **PASS** |
| RO questionnaire: one `page_view` | **PASS** |
| a contact link click emits `contact_click` with a categorical method | **PASS** |
| a form focus emits `lead_form_start` exactly once | **PASS** |
| focusing again emits no second `lead_form_start` | **PASS** |
| the conversion fires once with a same-origin referrer | **PASS** |
| **the submission id never reaches GA4** | **PASS** (was FAIL before the fix) |
| reloading thank-you does not double-count | **PASS** |
| thank-you without a same-origin referrer emits no conversion | **PASS** |
| no forbidden content in any beacon (12 scanned) | **PASS** |

The forbidden scan reads the page location, referrer, title and every event parameter of each
beacon and looks for e-mail addresses, phone shapes, lead ids, request ids, X-Ray and session ids,
cycle ids, submission keys, review tokens, initData and Telegram chat ids. GA4's own reserved
parameters are excluded deliberately: its session id is literally called `sid` and its page id is a
long number, and scanning those produced false positives on the first run.

### Duplicate and failure behaviour

- **reload** — the conversion is deduped in `sessionStorage` by submission id, proven by reloading
  the page and observing no second `generate_lead`;
- **repeat interaction** — `lead_form_start` is deduped per form and path, proven by focusing again;
- **validation failure as conversion** — impossible by construction: `generate_lead` fires only on
  `thank-you.html`, only with a recognised `tool`, and only after a same-origin referrer, which was
  tested and refused;
- **analytics failure never blocks the customer** — every sender is wrapped in try/catch,
  `trackBusiness` returns `false` rather than throwing, and a failed `gtag.js` load resets `loaded`
  and warns;
- **no double gtag load** — guarded by `loaded`, and confirmed live in both languages;
- **no duplicate listeners** — guarded by `businessTrackingMounted`.

Analytics is observational throughout: nothing in the submit path depends on it.
